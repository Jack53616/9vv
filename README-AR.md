# QL AI — إدارة تسجيل خروج المشتركين

هذه النسخة **سيرفر الترخيص + بوت إدارة تيليغرام**، وليست ملفات واجهة إضافة كروم.

## التعديلات

- زر **🔓 تسجيل خروج جميع المشتركين** ضمن قائمة بوت الإدارة وداخل «قاعة المشتركين»؛ يتطلب تأكيداً قبل التنفيذ.
- زر **🔓 تسجيل خروج الجهاز** داخل بطاقة المشترك النشط لفصل جهازه وحده.
- الأمر `/logoutall` للمشرفين فقط ويعرض شاشة التأكيد.
- مسار `POST /v1/logout` للمشترك نفسه، يشترط `token` و`deviceId` الحاليين.
- بعد الفصل، يستطيع المشترك إدخال **نفس مفتاحه** على أي جهاز والتفعيل من جديد. لا يتم إصدار كود جديد، ولا تمتد أيام الاشتراك عند إعادة تسجيل الدخول.
- انتهاء الصلاحية والإلغاء يظلان نافذين. لا يسمح باستخدام كود واحد على جهازين في الوقت نفسه.

## ربط زر تسجيل خروج بواجهة العميل

ليس في ملف ZIP الأصلي ملفات واجهة العميل. لذلك أضيف مسار السيرفر، ويجب على الإضافة أو تطبيق العميل استدعاؤه:

```js
// نفّذ هذا من زر تسجيل خروج العميل في الإضافة (مع بيانات الجلسة الحالية).
const response = await fetch(`${SERVER_URL}/v1/logout`, {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ token: currentToken, deviceId: currentDeviceId })
});
const result = await response.json();
if (result.ok) {
  // امسح الجلسة المخزنة محلياً واعرض شاشة إدخال الكود.
}
```

## الاختبار والتشغيل

1. انسخ الملفات إلى مشروع Render الحالي. احتفظ بنفس قاعدة بيانات MySQL أو قرص Render الموجود الذي يحوي `licenses.json`.
2. اضبط `TELEGRAM_BOT_TOKEN` و`ADMIN_IDS` (وبقية متغيرات قاعدة البيانات إن كنت تستخدم MySQL).
3. ثبّت الحزم: `npm ci` ثم شغّل `npm start`.
4. افتح بوت الإدارة، ثم «قاعة المشتركين» أو اضغط «🔓 تسجيل خروج جميع المشتركين» وأكّد.
5. تحقق من أن المشترك يُطلب منه إدخال الكود من جديد عند انتهاء الجلسة القديمة.

اختبارات تلقائية دون اتصال بالإنترنت: `npm test` (تعتمد على محاكاة Express وTelegram واختبار منطق ملفات المشروع الحقيقي).

### مهم بشأن الأكواد القديمة

الأكواد الموجودة محفوظة في قاعدة بيانات النشر الحالية **وليست مرفقة بهذا ZIP**. لا يمكن التأكد من كل كود موجود فعلياً دون الوصول إلى قاعدة بيانات النشر. إذا نشرته على خدمة Render جديدة بقاعدة بيانات فارغة، فستظهر الأكواد القديمة كغير معروفة. لا تستبدل ملف `licenses.json` الحي، ولا تغيّر اتصال MySQL أثناء التحديث.

الـ API يرجع `error: "device"` عند محاولة تفعيل الكود على جهاز آخر **قبل** تسجيل خروجه، و`error: "expired"` عند انتهاء الصلاحية، و`error: "revoked"` عند إلغاء الاشتراك، و`error: "invalid"` عند استخدام رمز جلسة قديم أو كود غير موجود. هذه حالات مقصودة، وليست أعطالاً بالبرنامج.
